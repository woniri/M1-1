# 🌦️ 서울 여름 기후 분석 & 9월 늦더위 전이 예측

> **분석 대상:** 서울특별시(기상청 ASOS 지점 108)
> **분석 기간:** 관측 2021~2026년 6월~8월(예측 포함) / 예측 2026년 9월
> **데이터 출처:** [공공데이터포털](https://www.data.go.kr) — 기상청_지상(종관, ASOS) 일자료 조회서비스 (실측)
> **🖥️ 인터랙티브 대시보드(보너스):** **https://seoul-summer.streamlit.app**

## 1. 프로젝트 개요

최근 5개년(2021~2025) 서울 여름철 기후와 올해(2026년) 여름을 비교해, 2026년이 실제로 더 더운 해였는지, 그리고 8월 말의 더위가 9월까지 이어질지를 통계적으로 살펴보는 시계열 데이터 분석 프로젝트입니다.

이 저장소는 데이터 분석 입문자를 위한 학습 미션의 결과물이며, **"질문을 정의하고 → 실측 데이터로 검증하고 → 관찰과 해석을 구분해 인사이트를 도출한다"**는 데이터 분석 사고 과정을 그대로 담고 있습니다.

## 2. 분석 질문 (3가지)

1. **[연도별 기온 추세]** 올해(2026년) 여름은 과거 5개년(2021~2025)과 비교할 때 실제로 더워졌는가?
2. **[극한 기후 분석]** 폭염(최고기온 33℃↑)일수와 열대야(최저기온 25℃↑)일수는 최근 5년간, 그리고 2026년에 어떻게 증감했는가?
3. **[9월 늦더위 전이]** 2026년 8월의 더위 기세가 9월까지 이어질 것인가? 언제쯤 가을다운 기온으로 내려갈 것인가?

답변은 `docs/REPORT.md`에서 확인할 수 있습니다.

## 3. AI와의 대화로 완성한 주제 선정 과정

이 프로젝트의 주제·범위·질문은 AI가 처음부터 일방적으로 정한 것이 아니라, 사용자와의 대화를 통해 5차례에 걸쳐 단계적으로 좁혀졌습니다(이전 세션에서 있었던 실제 대화 기록). 이 저장소는 그 결과로 확정된 주제를 이어받아, 코드와 문서를 새로 작성하고 오늘 날짜 기준 최신 실측 데이터로 다시 분석한 결과물입니다.

| 순서 | 대화 내용 | 결정 사항 |
| :--- | :--- | :--- |
| 1 | 사용자가 미션 원문을 공유하며 "초보자라 막막하니 단계별로 짧게 계획을 세워 하나씩 진행해달라"고 요청 | AI가 5단계 로드맵(주제→질문→수집→시각화→리포트)을 먼저 제시하기로 합의 |
| 2 | AI가 주제 후보 5가지 제시: ① 커피 브랜드 주가 ② 엔비디아/테슬라 주가 ③ 우리 동네 기온 ④ 비트코인 ⑤ 자유 주제 | — |
| 3 | 사용자 "일단 기온/날씨 데이터로" | 계절성과 이상치가 뚜렷해 시계열 분석 입문에 적합하다는 이유로 확정 |
| 4 | 사용자 "서울로 진행 / 최근 5년 자료 / 여름 한정으로 조사해보고 싶다" | 대상: 서울, 기간: 2021~2025년, 계절: 여름(6~8월)로 범위 축소 |
| 5 | 사용자 "9월까지 포함했으면 좋겠다" | 늦더위 이슈 반영을 위해 분석 기간을 6월~9월로 확장 |
| 6 | 사용자 "올해와 비교하고 9월을 예측해보고 싶다" | 분석 목적이 '과거 5개년 기술(記述)'에서 '올해 실측 vs 과거 비교 + 9월 예측'으로 확장 |

**핵심 교훈**: 처음 계획은 "5개년 기온 데이터를 기술 통계로 보여주는 것"이었지만, 대화를 거치며 "**올해가 얼마나 이례적인 해였는지 검증하고, 앞으로 다가올 9월을 예측한다**"는 더 뾰족하고 실용적인 질문으로 진화했습니다. 데이터 분석에서 "질문을 다듬는 과정 자체가 분석"이라는 것을 보여주는 사례입니다.

## 5. 실행 방법 (Docker 기반, venv 사용 안 함)

### 5.1 API 키 없이 바로 실행 (추천 — 저장소에 이미 실측 데이터가 포함되어 있음)

이 저장소에는 이미 수집된 실측 CSV(`data/*.csv`)가 포함되어 있어서, **기상청 API 키가 없어도** 아래 두 명령만으로 분석·시각화를 바로 재현할 수 있습니다.

```bash
./run.sh build      # 최초 1회, Docker 이미지 빌드
./run.sh analyze    # 분석 실행 + images/에 차트 5개 생성 (이동평균·변화율 포함)
./run.sh timeseries # (선택, 보너스) STL 분해 + 예측 모델 백테스트
./run.sh dashboard  # (선택, 보너스) 인터랙티브 대시보드 기동 → http://localhost:8501
./run.sh tutorial   # (선택) 초보자용 판다스 실습 스크립트
```

### 5.2 데이터를 직접 새로 수집하고 싶다면 (API 키 필요)

데이터를 최신 날짜 기준으로 다시 받아오거나, 다른 지역으로 재사용하려면 기상청 API 키가 필요합니다.

```bash
# 1) https://www.data.go.kr 에서 "기상청_지상(종관, ASOS) 일자료 조회서비스" 활용신청 → 인증키 발급
# 2) 키를 환경변수로 전달(코드/커밋에는 절대 저장되지 않음)
export KMA_SERVICE_KEY="발급받은_인증키"
./run.sh fetch
./run.sh analyze
```

다른 지역/기간으로 재사용하려면:

```bash
./run.sh fetch --station-id 159 --start-year 2019 --end-year 2024 --location-name 부산
```

> ⚠️ 인증키는 개인 계정에 귀속됩니다. `run.sh fetch`는 호스트의 `KMA_SERVICE_KEY` 환경변수를 컨테이너 실행 시점에만 전달하며, 이미지·코드·커밋 어디에도 저장하지 않습니다.

## 7. 핵심 결과 요약 (기상청 실측 데이터 기준, 2026-08-24까지 관측)

| 구분 | 2021 | 2022 | 2023 | 2024 | 2025 | **2026** | 과거 5개년 평균 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 평균기온 | 25.63℃ | 25.48℃ | 25.78℃ | 26.87℃ | 27.05℃ | **26.25℃** | 26.16℃ |
| 폭염일수(≥33℃) | 18일 | 10일 | 19일 | 27일 | 27일 | **15일** | 20.2일 |
| 열대야일수(≥25℃) | 20일 | 20일 | 18일 | 35일 | 44일 | **22일** | 27.4일 |

- 2026년 여름 평균기온은 과거 5개년 평균 대비 **+0.09℃**로 사실상 차이가 없는 수준
- **폭염·열대야 일수는 오히려 과거 평균보다 적음**(폭염 -5.2일, 열대야 -5.4일) — 2024~2025년이 특히 더웠던 해였고, 2026년은 상대적으로 온건
- **9월 예측(통계 모델)**: 상순 평균 최고 29.3℃ → 하순 26.6℃로 낮아지며, 추가 폭염·열대야는 0일로 예측

자세한 근거와 해석은 `docs/REPORT.md`를 참고하세요.

## 9. 향후 발전 과제

1. **9월 실측 검증**: 실제 9월이 지나면 `./run.sh fetch`를 재실행해 9월 예측치(폭염·열대야 0일 예측)가 실제와 얼마나 맞았는지 검증하고 `REPORT.md`에 "사후 검증" 절을 추가
2. **장기 데이터 확보**: 6년보다 긴 기간(10~30년)의 데이터를 추가 수집해 "온난화 추세"를 통계적으로 더 신뢰성 있게 검증 (`docs/REPORT.md` 한계점 참고)
3. **원인 변수 추가**: 2026년 7월이 왜 평년보다 선선했는지 설명하기 위해 강수량·장마 기간 데이터를 추가 수집
