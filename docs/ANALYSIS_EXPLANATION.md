# 📖 분석 수식 및 차트 심층 해설

이 문서는 `analysis.py`/`fetch_kma_data.py`가 내부적으로 어떤 계산을 하는지, 각 차트가 무엇을 보여주는지 설명합니다.

## 1. 데이터 파이프라인 개요 — 로딩 → 정제 → 분석 → 시각화

이 프로젝트는 4단계로 나눠 실행됩니다. 각 단계는 별도 스크립트/함수로 분리되어 있어, 한 단계의 결과가 다음 단계의 입력이 되는 구조입니다.

| 단계 | 담당 코드 | 하는 일 |
| :--- | :--- | :--- |
| ① 로딩(수집) | `fetch_kma_data.py::collect_observed()` | 기상청 API를 호출해 원본 JSON 응답을 받아 데이터프레임으로 변환 |
| ② 정제 | `fetch_kma_data.py::collect_observed()` 후반부 | 타입 변환(`pd.to_numeric`), 결측치 탐지 및 선형보간(3장), 폭염/열대야 플래그 생성 |
| ③ 분석 | `analysis.py` Step 2 | `groupby`로 연도별/월별 집계, 평년 편차(anomaly) 계산, 누적합 계산 |
| ④ 시각화 | `analysis.py` Step 3~6 | matplotlib/seaborn으로 4개 차트 생성 후 `images/`에 PNG 저장 |

수집(①)과 정제(②)는 `fetch_kma_data.py` 한 파일 안에서 순서대로 실행되고, 그 결과(CSV 3개)를 `analysis.py`가 읽어 분석(③)·시각화(④)를 수행합니다 — 두 스크립트를 분리한 이유는 "데이터를 새로 받아오는 것"과 "이미 있는 데이터를 분석하는 것"을 독립적으로 실행할 수 있게 하기 위해서입니다(API 키가 없어도 ③·④는 항상 가능).

## 2. 폭염·열대야 판정 기준

- **폭염(is_heatwave)**: 해당 일의 최고기온(`max_temp`) ≥ 33.0℃
- **열대야(is_tropical_night)**: 해당 일의 최저기온(`min_temp`) ≥ 25.0℃

기상청이 실제로 사용하는 공식 정의(폭염특보 기준 등)를 단순화한 값으로, `fetch_kma_data.py`에서 이 두 상수(`HEATWAVE_THRESHOLD`, `TROPICAL_NIGHT_THRESHOLD`)만 바꾸면 다른 기준으로 재계산할 수 있습니다.

## 3. 결측치 처리 — 선형보간(Linear Interpolation)

기온 관측값이 API 응답에서 비어 있는 경우, `df.interpolate(method="linear")`로 처리합니다. 이는 결측 지점 앞뒤의 실측값을 직선으로 이어 그 사이 값을 추정하는 방법입니다. 예를 들어 6/10일이 결측이고 6/9일이 24℃, 6/11일이 26℃라면 6/10일은 25℃로 채워집니다. 시계열 데이터에서 가장 단순하고 보수적인 결측 처리 방법입니다.

**왜 삭제나 평균 대체 대신 선형보간을 선택했는가**: 결측이 딱 1건뿐이고 앞뒤 날짜의 실측값이 모두 존재하는 상황에서는, 그 행을 통째로 삭제하면(위 1건 기준 552행 중 1행) 시계열의 날짜 연속성이 끊깁니다(6~8월 매일 데이터를 전제로 계산하는 누적합·연속 스트릭 계산에 영향). 전체 평균이나 중앙값으로 채우면 그날 전후의 실제 기온 흐름(예: 더워지는 중이었는지 식는 중이었는지)을 무시하게 됩니다. 선형보간은 "결측일 전후 며칠은 보통 비슷하게 변한다"는 시계열 데이터의 자연스러운 성질을 그대로 활용하는, 가장 단순하면서도 왜곡이 적은 절충안입니다.

## 4. 9월 늦더위 전이 예측 모델 — "평년값 + 감쇄 편차"

`build_forecast()` 함수의 핵심 아이디어:

1. **평년값(Climatology)**: 과거 연도들의 같은 날짜(월-일) 평균기온을 구합니다. 예: 과거 5개년의 "9월 5일" 평균기온.
2. **올해 편차(Anomaly)**: 올해 실측 구간(6~8월)에서 "실측값 − 그날의 평년값"의 평균을 구합니다. 이 값이 양수면 올해가 평년보다 더웠다는 뜻입니다.
3. **감쇄(Decay)**: 예측 구간(9월)의 각 날짜에 이 편차를 그대로 더하지 않고, 시간이 지날수록 편차의 영향력을 선형으로 줄여서(`np.linspace(1.0, 0.2, n)`) 더합니다. 예측 첫날은 편차의 100%를, 예측 마지막 날은 20%만 반영합니다 — "여름의 기세가 시간이 지나며 약해진다"는 가정을 수식으로 표현한 것입니다.

`예측값 = 그날의 평년값 + (올해 편차 × 감쇄계수)`

이 모델은 **실제 수치예보가 아닌 통계적 baseline 추정**입니다. 태풍, 대기 정체 같은 단기 기상 현상은 반영하지 못하므로, 실제 9월이 지나면 `fetch_kma_data.py`를 다시 실행해 예측과 실측을 비교(사후 검증)해보는 것을 권장합니다.

## 6. 핵심 개념 요약

| 개념 | 이 프로젝트에서의 의미 |
| :--- | :--- |
| 트렌드(Trend) | 여러 해에 걸친 장기적인 방향성 (예: 폭염일수가 계속 느는가) |
| 계절성(Seasonality) | 매년 6월에 시작해 8월에 정점, 9월에 하락하는 반복 패턴 |
| 노이즈(Noise) | 트렌드·계절성으로 설명되지 않는 하루하루의 미세한 변동(차트 2의 들쭉날쭉한 실선) |
| 편차(Anomaly) | "오늘 값 − 평년 평균값" — 절대값보다 이례성을 잘 보여줌 |
| 감쇄(Decay) | 예측에서 최근 관측의 영향력을 시간에 따라 점점 줄이는 기법 |
| 관찰(Fact) vs 해석(가설) | 관찰은 숫자로 확인되는 사실, 해석은 그에 대한 추정(틀릴 수 있음) |

## 7. (보너스 심화) STL 시계열 분해 및 예측 모델 백테스트

`timeseries_advanced.py`는 6장의 "트렌드/계절성/노이즈"라는 정성적 개념을, 실제 통계 기법(STL)으로 **정량적으로 분리**하고, 9월 예측에 **두 번째 모델을 추가로 검증**합니다. `./run.sh timeseries`로 재현할 수 있습니다.

### 7.1 STL 분해 — 5개년(2021~2025) 여름 사이클을 이어붙여 분해

일별 관측치는 6~9월(122일)만 존재하고 10~5월은 비어 있어, 달력상의 연속된 1년 주기로는 분해할 수 없습니다. 대신 **"6/1을 1일차로 하는 122일짜리 여름 사이클"을 5개년치 이어붙여(총 610일) 주기(period)=122로 STL 분해**했습니다 — 즉 "연도가 바뀔 때마다 반복되는 여름 내부의 상승-하강 패턴"을 계절성으로, "그 반복 패턴 자체가 해마다 얼마나 높아지고 낮아지는지"를 추세로 분리하는 방식입니다.

| 성분 | 결과 | 의미 |
| :--- | :--- | :--- |
| 추세(Trend) | 2021년 초입 평균 24.84℃ → 2025년 말미 평균 25.99℃ (**+1.15℃**) | 5개년 사이 여름철 기저 기온이 완만히 상승 |
| 계절성(Seasonal) | 사이클 54일차(≈7/24 전후)에서 정점, 진폭 **12.34℃** | 매년 반복되는 "6월 서늘 → 7월 말 정점 → 9월 하강" 패턴의 크기 |
| 잔차(Residual) | 표준편차 **1.67℃** | 추세·계절성으로 설명 안 되는 순수 날씨 노이즈(폭염 스파이크, 갑작스러운 냉각 등) |

잔차가 가장 컸던 날(=계절성·추세로 예상되는 범위를 크게 벗어난 이례적인 날)을 뽑아보면:

- **이례적 고온 Top3**: 2024-09-19(+6.88℃), 2024-06-21(+6.16℃), 2022-07-03(+6.14℃)
- **이례적 저온 Top3**: 2022-07-21(-6.56℃), 2024-07-09(-6.24℃), 2023-08-10(-5.90℃)

2024년이 고온·저온 잔차 모두에 등장한다는 점이 흥미로운데, 이는 2024년 여름의 평균이 높았다는 것(추세)과는 별개로 **일교차·날씨 변동성 자체도 컸던 해**였음을 보여줍니다(2024년이 폭염 27일·열대야 35일로 극값이 몰렸던 것과 같은 맥락, 5장 참고).

### 7.2 예측 모델 백테스트 — 베이스라인(평년+편차감쇄) vs Holt 지수평활

4장의 "평년값+편차감쇄" 모델이 실제로 얼마나 정확한지 검증하기 위해, **통계적으로 더 정교한 대안 모델(Holt 지수평활 — `statsmodels.tsa.holtwinters.ExponentialSmoothing`, 추세 포함·감쇠추세)**을 추가로 구현하고, **5개년 leave-one-year-out 백테스트**로 정면 비교했습니다.

**방법**: 5개년(2021~2025) 각각을 돌아가며 "그 해라고 가정"하고 6~8월 실측만 보여준 뒤 9월을 예측시키고, 실제 9월 실측치와의 평균절대오차(MAE)를 계산합니다.

| 백테스트 연도 | 베이스라인 MAE | Holt MAE |
| :---: | :---: | :---: |
| 2021 | 1.37℃ | 1.32℃ |
| 2022 | 1.55℃ | 2.31℃ |
| 2023 | 1.36℃ | 2.17℃ |
| 2024 | 2.27℃ | 2.81℃ |
| 2025 | 1.63℃ | 5.05℃ |
| **5개년 평균** | **1.64℃** | **2.73℃** |

**결과**: 5개년 중 4개년에서 베이스라인이 더 정확했고, 평균 MAE도 베이스라인(1.64℃)이 Holt(2.73℃)보다 낮았습니다. 원본 데이터는 `data/forecast_backtest_results.csv`, 비교 차트는 `images/06_forecast_backtest_comparison.png`에 있습니다.

**왜 "더 정교해 보이는" 모델이 오히려 졌는가**: Holt 지수평활은 계절성 성분이 없는 순수 추세 모델입니다. 6~8월 관측 구간 안에서는 기온이 계속 오르는 국면(계절성의 상승 구간, 7.1절의 계절성 곡선 참고)이라, Holt는 이 상승 기울기를 "앞으로도 계속될 추세"로 착각해 9월에도 그대로 연장합니다. 실제로 2026년 9월에 이 모델을 적용해 보면 **평균기온이 9/1 28.9℃ → 9/30 29.8℃로 오히려 계속 오르는 것으로 예측**하고(베이스라인은 24.7℃ → 20.7℃로 하강), 그 결과 열대야를 24일이나 있을 것으로 잘못 예측합니다(베이스라인·실제 기후 패턴 모두 0일에 수렴). 반면 베이스라인은 "평년값(그 날짜 자체가 원래 얼마나 더운 날인지)"을 기준점으로 삼기 때문에, 계절이 꺾이는 시점(9월 하강)을 모델이 몰라도 평년값 자체에 이미 반영되어 있어 구조적으로 유리합니다.

**교훈**: 모델이 통계적으로 더 정교하다고 항상 더 정확한 것은 아니며, **문제의 구조(계절 전환점을 지나는 예측)에 모델의 가정이 맞는지**가 더 중요합니다. 이는 4장의 베이스라인 모델을 그대로 채택하는 것에 대한 정량적 근거이자, "인사이트를 검증하려 시도했지만 반증된" 사례이기도 합니다. 전체 비교 결과는 `data/september_forecast_model_comparison.csv`에서 확인할 수 있습니다.
